# Архитектура Makise

Статус: зафиксированная архитектурная база V1  
Дата: 2026-08-05  
Связанные документы: [VISION.md](VISION.md), [PROTO.md](PROTO.md), [MEMORY.md](MEMORY.md), [SECURITY.md](SECURITY.md), [INVARIANTS.md](INVARIANTS.md)

## 1. Главный принцип

Makise строится как событийная система с независимым миром и асинхронным мозгом. Мир не останавливается во время запросов к LLM, памяти или медиапровайдерам.

`makise-world` — единственный автор объективного состояния. Brain получает ограниченное восприятие и отправляет команды. Ни LLM, ни панель, ни memory service не пишут состояние мира напрямую.

## 2. Компоненты

| Компонент | Технология | Ответственность |
|---|---|---|
| `makise-world` | Rust | время, квартира, тело, affect, мотивация, действия, восприятие, event log и snapshots |
| `makise-brain` | C++, fork kuni | Telegram/TDLib, сборка контекста, вызов LLM, выбор команд и координация инструментов |
| `makise-memory` | отдельный сервис новой памяти | субъективные события, retrieval, консолидация, сущности, отношения и рабочая память |
| `makise-panel` | TypeScript, React, SVG | карта, timeline, decision trace, метрики и безопасные административные действия |
| `makise-gateway` | локальный backend | аутентификация панели, урезанный внешний API, HTTPS/WSS и аудит |
| model adapters | независимые адаптеры | main/fallback LLM, code LLM, image, TTS и STT |
| admin notifier | отдельный канал | технические уведомления без команд управления |

## 3. Источники истины

| Данные | Источник истины |
|---|---|
| Объекты, комнаты, положение, таймеры, тело | `makise-world` |
| Фактически выполненные действия | durable event log мира |
| Субъективный опыт и отношения | `makise-memory` |
| Текущие намерения и обязательства | world goal state + working memory |
| Исходная идентичность | версионированный identity package |
| Личный дневник | append-only diary Makise |
| Техническая конфигурация | версионированный TOML |
| Секреты | отдельный secret store |

Память не исправляет мир, а мир не создаёт субъективное воспоминание без восприятия.

## 4. Основной поток решения

```text
внешнее/внутреннее событие
  -> запись объективного WorldEvent
  -> построение PerceptionWindow
  -> subjective event и retrieval памяти
  -> запуск единственного BrainDecision
  -> команда с command_id и world_version
  -> детерминированная проверка
  -> запись результата в event log
  -> обновление состояния
  -> новое восприятие и, при значимости, память
```

### 4.1 Последовательное сознание

- Одновременно существует не более одного основного запроса к LLM.
- Новые события во время размышления попадают в `while-thinking buffer`.
- Критическое событие инвалидирует устаревший ответ.
- Обычные события объединяются в следующую компактную сводку.
- Отдельные модели могут классифицировать или анализировать код, но не принимают решения от имени Makise.

### 4.2 Состояния доступности мозга

- `READY`: можно запустить новое осознанное решение.
- `THINKING`: основной запрос в процессе.
- `WAITING_FOR_COGNITION`: требуется решение, но модель недоступна или достигнут лимит.
- `SLEEPING`: LLM не вызывается без допустимого события пробуждения.

Если Brain недоступен, уже подтверждённые безопасные шаги и фоновые процессы продолжаются. Новые решения движок не выдумывает.

## 5. Модель мира внутри Rust

Используется гибрид типизированных компонентов и доменных state machine без тяжёлого игрового ECS:

- сущности имеют стабильные типизированные ID;
- компоненты описывают положение, контейнеры, поверхности, питание, заряд, температуру, чистоту, звук и другие свойства;
- системы вычисляют время, сенсорные поля, потребности, affect и доступные действия;
- сон, готовка, телефон, доставка и планы имеют явные автоматы состояний;
- изменяемым состоянием владеет один writer thread;
- Tokio-задачи обслуживают транспорт, таймеры и внешние API, но отправляют команды владельцу через ограниченную очередь;
- UI-координаты являются производным представлением и не участвуют в правилах.

## 6. Действия и параллельность

Вместо глобального `BUSY` действие резервирует ресурсы:

- `movement`;
- `hands`;
- `vision`;
- `attention`;
- `speech`;
- `hearing`;
- `background`.

Совместимые действия выполняются параллельно: можно слушать музыку во время уборки или ждать кофе во время чтения телефона. Конфликтующие действия отклоняются или ждут безопасной точки.

Прерываемость задаётся как `immediate`, `safe_point`, `non_interruptible_until_step` или `background`.

## 7. Мотивация и Affect Engine

Кандидаты действий непрерывно пересчитываются при изменении состояния. Источники кандидатов:

- телесные потребности;
- обещания, планы и незавершённые разговоры;
- бытовые обязательства;
- самостоятельные проекты и интересы;
- привычки и циркадные ритмы;
- реакция на события среды.

World Engine фильтрует невозможное и вычисляет причинную срочность. LLM выбирает среди допустимых кандидатов. Активная цель получает гистерезис, чтобы Makise не металась между занятиями.

Affect Engine объединяет физиологию, непрерывный core affect, краткие emotion episodes, appraisal значимых событий, инерцию, регулирование и устойчивые черты. LLM может вернуть структурированную семантическую оценку, но не устанавливает числовое настроение напрямую.

## 8. Время и выключение компьютера

- Production использует реальное время 1:1.
- Абсолютные дедлайны хранятся в UTC.
- Интервалы активного процесса измеряются monotonic clock.
- Новосибирский часовой пояс используется для распорядка и отображения.
- Большой скачок времени переводит мир в `TIME_ANOMALY`.
- После downtime вычисляются только пассивные причинные последствия.
- Если Makise бодрствовала, она замечает разрыв времени; если спала, допустимый интервал засчитывается как сон.
- Активные действия без автономного физического продолжения ставятся на безопасную паузу.

Тестовый экземпляр использует управляемые виртуальные часы и отдельный `identity_id`.

## 9. Транспорт и хранение

- Внутренний горячий контур: Protobuf по постоянному Unix Domain Socket.
- Панель: HTTPS/JSON и WebSocket через gateway.
- Каждая команда несёт `command_id`, `world_version`, `agent_id` и версию схемы.
- События имеют монотонный `event_seq`.
- Команда подтверждается только после durable commit.
- Повтор команды с тем же ID возвращает прежний результат.
- SQLite работает в WAL-режиме; event log является append-only.
- Snapshots ускоряют запуск, но могут быть восстановлены из журнала.

Подробности определены в [PROTO.md](PROTO.md).

## 10. Развёртывание

Исходники находятся в монорепозитории:

```text
/home/artem/makise/
├── brain/
├── world/
├── memory/
├── panel/
├── proto/
├── world-packages/
├── identity/
├── deploy/
└── tests/
```

Runtime расположен только в `/home/artem/makise_run`. Нативные systemd-сервисы запускаются от отдельного пользователя ОС `makise`, получают секреты через systemd credentials и используют атомарные release-каталоги.

Одновременно активен только один процесс с данным `identity_id`. Lease/lock защищает от раздвоенного запуска.

## 11. Наблюдательная панель

Панель read-only по умолчанию. Она показывает:

- визуальную карту и семантический граф;
- текущую деятельность, ресурсы и оставшееся время;
- воспринятые факты, извлечённые воспоминания и активные цели;
- структурированную причину выбора без раскрытия скрытого chain-of-thought;
- технические метрики, стоимость и cache hit;
- timeline событий и состояние резервных копий.

Аварийные действия ограничены [SECURITY.md](SECURITY.md) и всегда аудитируются.

## 12. Независимые провайдеры

Основная, резервная и кодовая LLM, image-provider, TTS и STT настраиваются раздельно. Адаптер профилирует поддержку tools, structured output, streaming, cache hints и предел контекста.

Смена модели не меняет память или идентичность. Автоматический fallback разрешён только явной политикой. Ошибки 400/422/429 и неизвестные статусы не приводят к бесконечному retry.
